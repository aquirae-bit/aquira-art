# Aquira Wix UI修正：フィードとフッターの分離

## 対象と判断

本番HTMLの確認により、外部ソーシャルフィードは Wix の `SITE_FOOTER` 内で `#comp-maz1kmkp` として描画され、フィード本体は `https://app.socialstream.io/wix/widget` を指すクロスオリジンiframeであることを確認した。さらに、`#aquira-footer-sitemap` と `#aquira-footer-shell` のカスタムフッターが Body end に追加されている。問題は、外部iframeの内部UIではなく、Wixフッター・外部ウィジェット・カスタムフッターの親レイヤーが同じ視覚帯で競合し、幅・高さ・積層・背景面の責務が分離されていないことである。

`wix-ui-remediation-embed.js` は、上記の既知のWix要素だけを対象に、以下を実施する。

| 修正項目 | 実装内容 | UX上の効果 |
|---|---|---|
| レイヤー分離 | `SITE_FOOTER` を通常フロー・独立スタッキングコンテキスト・横方向クリッピングへ統一 | フィードやフッターが互いの背景面へ侵入しない |
| フィード拘束 | `#comp-maz1kmkp` を画面幅から余白を引いた最大980pxのコンテナに固定 | 超横長画面でもフィードが無制限に伸びず、左右の余白が一定になる |
| フッター保護 | sitemap とカスタムフッターを独立した通常フローの黒背景面として強制 | ソーシャルフィードの白い面や外部サービスバーがフッターリンクと衝突しない |
| レスポンシブ | 狭幅時には安全な横余白と高さ上限を設定 | 横スクロール、本文切断、背景の白抜けを防ぐ |
| アクセシビリティ | iframeの名称と外部コンテンツ説明を追加し、フォーカス時の輪郭を明示 | スクリーンリーダーとキーボード操作でコンテンツの性質を理解できる |
| 補助UIの優先度 | ビルダー由来バッジと未読チャット通知を対象ID・ARIAラベルに限定して非表示化し、Cookie設定を右下の控えめな再訪問トリガーへ移設 | 作品・フィード・フッターを遮らず、必要なCookie設定へのアクセスは残す |

## 反映方法

このスクリプトはWixの全ページで読み込む前提の、単独・依存なしのコードである。既存のアクセシビリティ用スクリプトとは干渉しない。Wixのカスタムコード設定で `wix-ui-remediation-embed.js` の内容を Body end・全ページ・一回のみ読み込みとして追加し、公開前にデスクトップ・タブレット・モバイルのプレビューを確認する。

> iframe内部の `Powered by SocialStream.io` などは外部サービス側の表示であり、クロスオリジン制約と提供元表記の観点から、この修正では隠蔽しない。ページ側のコンテナ・背景・位置を整え、ブランドUIとの視覚的衝突を解消する。

> Cookie同意バナー本体は対象外とし、すでに同意処理が完了した後に表示される「Cookie 設定」再訪問トリガーだけを調整する。未読チャット通知を隠しても、チャット起動そのものは変更しない。

## 検証観点

デスクトップでは、フィードが画面中央の最大980pxを越えず、フィードの終端後に黒いフッター面が連続して始まることを確認する。狭幅では、フィードがビューポートからはみ出さず、横スクロールバーが出ないことを確認する。すべての幅で、フッターのリンク群が白いフィード面の背後に入らず、iframeへフォーカスしたときに視認可能な輪郭が表示されることを確認する。
